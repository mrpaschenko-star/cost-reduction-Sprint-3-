# Sourcing Strategy

Buy применяется к стандартным процессам при доказанной совместимости, Build — к собственной логистике и правилам интеграции, Migrate — к инфраструктуре этих продуктов. Облако не устраняет локальный HAL, фискальные ограничения и стоимость эксплуатации периферии.

| Возможность | Решение и размещение | Обоснование / отвергнутая альтернатива | Условия и ответственный |
|---|---|---|---|
| Продажа, смена, возвраты, ценники | **SaaS Buy:** Cloud POS с управляемым приложением | Функции стандартны. Собственная новая касса создаёт дорогой цикл тестирования и фискальных обновлений | Store Ops: offline cash, экспорт данных, поддержка 2 касс/магазин, MDM и подписанный каталог, цена по магазину/кассе |
| HAL и платёжная интеграция | **Buy SDK/adapters + собственный стабильный port**, исполнение на планшете | Убирать прямые драйверы из POS. Только облачный gateway не может обращаться к USB | Store Ops: матрица устройств/ОС/прошивок/эквайеров, сертификация; непокрытые модели заменять по TCO |
| Лояльность и коммуникации | **SaaS Buy**, централизованное владение | Тетрадки и разрозненные балансы заменяются одним ledger бонусов. Offline spending без лимитов создаёт двойное списание | Маркетинг: согласия, residency, API, pending accrual, запрет offline redemption в пилоте |
| Кадры и премии | **In-house/on-premises: существующий SAP**, консолидация | Повторная закупка HR SaaS сейчас дублировала бы уже оплаченный процесс ERP | HR/финансы: формулы премий и права; локальные таблицы перестают быть источником расчёта |
| SKU master, закупки, финансы, приёмка | **In-house/on-premises: SAP**, адаптеры и мобильный UI | Наличие SAP — факт; лицензии/локализация/договоры и готовность миграции не исследованы. «Мощный SAP» сам по себе не доказательство избыточной стоимости | IT и финансы: аудит лицензий, API/import, объёмы. Отдельный бизнес-кейс миграции SAP после стабилизации магазинов |
| Promo Engine | **PaaS Migrate**, сохранить код на первом этапе | Единый двигатель уже есть. Его уникальность не доказана; переписывание или замена сейчас добавит риск ценовых расхождений | Коммерческий/IT: контракт версий промо; сравнить стоимость с функцией SaaS после пилота |
| Smart Fulfillment, Click & Collect | **Build in Cloud**, собственный продукт на PaaS | Это заявленное конкурентное преимущество. Готовый OMS можно использовать как инфраструктуру лишь без потери уникальных правил | Продукт логистики: владение кодом и данными, резервирование остатков, SLO и миграция без двойного владения заказом |
| SKU Matching | **Build orchestration + Buy inference**, PaaS | Детерминированные проверки и human approval — свои; модель извлечения/ранжирования — управляемый сервис. ИИ не получает права изменять SAP | Data Integration: calibrated precision, golden set, ограниченные candidate IDs, audit и экспорт labels |
| Мониторинг, backup, очереди, БД интеграции | **PaaS Buy** | Не дают конкурентного преимущества; управляемые сервисы уменьшают on-call нагрузку | IT: измерить стоимость storage/egress/logs, RPO/RTO, restore и выход из платформы |
| Управление устройствами и Service Desk | **SaaS Buy**, MDM + действующий Service Desk | Удалённые релизы и диагностика уменьшают выезды. Не менять Service Desk только ради перехода в облако | Store Ops: staged rollout, revocation, запрет удалённого wipe при несинхронизированных продажах |
| Фискальное устройство / локальный journal | **Локальное исполнение**, купленное сертифицированное ПО | Для offline cash нужны физический регистратор, драйвер и durable queue. Это не отдельный сервер магазина | Store Ops: журнал на планшете, сохранность ФН, контроль питания, допустимые офлайн-операции по категориям товаров |

## Выбранный стек и закупочные условия

Для интеграционной платформы выбран **Yandex Cloud**: Managed Service for PostgreSQL (jobs, mappings, receipts inbox), Object Storage (исходные файлы и версии каталогов), Message Queue (at-least-once фоновые задания), Serverless Containers (адаптер ERP и SKU workers), IAM/KMS/Lockbox, Monitoring/Logging, VPN к HQ. Smart Fulfillment и Promo Engine переносятся на управляемую вычислительную среду после аудита runtime; контейнерный кластер вводится только при реальной потребности этих приложений. Для модели — управляемый inference с договором об обработке данных; регион и политика обучения/хранения проверяются. Эти сервисы не означают, что SAP или POS автоматически совместимы с их API.

Для Cloud POS выбран **класс SaaS с локальным offline SDK/HAL**, а не безусловно конкретный вендор. В материалах нет каталога поддерживаемых устройств и коммерческих предложений. В течение первых четырёх недель проводится RFP минимум двух поставщиков: обязательны демонстрация ARCUS-2 на фактическом устройстве/прошивке, USB-фискализация на выбранной ОС, offline cash/replay, API экспорта и migration exit. Облачная витрина без локального SDK исключается. Подписка 5 000 ₽/магазин/месяц в TCO — допущение для двух касс, не предложение Yandex Cloud или POS-поставщика.

Критерии с весами: функциональная/фискальная совместимость 30%, offline и восстановление 25%, TCO 20%, интеграции и экспорт 15%, поддержка/безопасность 10%. Провал обязательного теста не компенсируется баллами. В SLA фиксируются доступность облака, автономность, сроки устранения, формат экспорта; отдельная цена HAL/MDM исключается из модели, если уже включена в SaaS. Затраты разработки нестандартного драйвера оцениваются отдельно: «адаптация к любым терминалам» без теста не обещается.

Риск lock-in снижают собственные SKU/store IDs, выгрузка mappings и чеков, открытый receipt envelope, versioned adapters, проверенный экспорт и лимит стоимости выхода. Уникальная бизнес-логика Smart Fulfillment не передаётся POS-вендору. Решение по SAP не обосновывается выдуманным запретом на облако: пока есть только отсутствие доказательств экономической и технической готовности к его миграции.
