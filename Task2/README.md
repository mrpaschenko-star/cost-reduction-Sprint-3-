# Задание 2 — онбординг магазина

Результаты: [процесс и верификация](onboarding.md), BPMN 2.0 [PNG](diagrams/onboarding.png), [SVG](diagrams/onboarding.svg), [исходник .bpmn](diagrams/onboarding.bpmn).

Пулы разделяют координатора магазина/Store Ops, платформу онбординга, ИИ-сервис, товароведа HQ и SAP ERP. Сплошные sequence flows остаются внутри пула; пунктирные message flows пересекают границы участников. Автоматическое сопоставление формирует auto-match и исключения; товаровед проверяет исключения и выборку auto-match перед общим quality gate и staging-импортом ERP. Ошибки данных/проверки дают явный возврат на исправление. `.bpmn` содержит BPMNDI и предназначен для редактора BPMN; привязки к runtime/workers для запуска процесса не входят в проект.

Весь импорт коррелируется по `store_id + batch_id + source_hash + master_version`. Реальное открытие магазина происходит после получения пакета из ERP и проверки оборудования, цены и offline cash, а не после окончания вызова модели.
