# Проверка исходных артефактов

Исходная схема — гипотеза из wiki, а не достоверное описание production. При противоречии приоритет имеют действующий регламент и конкретное наблюдение; непроверенные детали не объявляются фактами.

| Утверждение / наблюдение | Источник | Вывод и изменение AS-IS |
|---|---|---|
| POS → SAP REST real-time stock/loyalty | Артефакт 1 | Не подтверждено. Убрана прямая real-time связь как описание товарного обмена |
| SAP отправляет XML в 02:00 по FTP на Local DB | Регламент 7.1, артефакт 2 | Показан ночной пакетный обмен через локальный импорт; точный механизм выгрузки продаж обратно в SAP неизвестен |
| HQ Cloud | Заголовок границы артефакта 1 | Описание компании говорит SAP on-premises. На исправленной схеме HQ обозначен on-premises |
| Лояльность работает через SAP | Артефакт 1 | INC-8402 подтверждает внешнюю online-зависимость, но не её реализацию. Backend обозначен «требует уточнения», не приписан SAP |
| Интернет пропал — наличные чеки работают, loyalty timeout | INC-8402 | Ограниченный offline есть сейчас. Табличка «только наличные» не доказывает, что все банковские терминалы технически не могут работать со своим каналом |
| SQL Express | Подпись БД артефакта 1 | В кейсе есть MS SQL/PostgreSQL и платные лицензии. Не считать все 500 магазинов одним тарифом SQL Express; аудит inventory/license нужен для TCO |
| Отказ локального диска останавливает магазин | INC-8433 | Локальная DB/server — SPOF для данного магазина. 4–6 ч — ETA инженера, не доказанный полный RTO |
| Новая модель терминала требует три недели разработки | INC-8415 | Драйверы жёстко связаны с кассой. ARCUS-2/модель/прошивка — предмет теста; наличие названия протокола не гарантирует SDK для планшета |
| Две недели на сопоставление, 80% вручную | Интервью и регламент | Высокая доля ручных действий доказана по интервью; норматив 500/ч не равен календарному сроку открытия |
| 15% ошибок, 10 000 позиций | Условия задания 2 | Принято как исходная оценка кейса; метод измерения неизвестен, перед пилотом нужна единая метрика |
| Локальные премии/приёмка/тетрадки дублируют HQ | Условия задания 1 | Отражены в карте возможностей и sourcing; не выдуманы отсутствующие API |

Исправленная AS-IS показывает толстый POS/back-office, локальную DB, драйверы и устройства, ночную загрузку прайсов, ручной CSV/XLS/email → товаровед → SAP, внешний online backend лояльности с неизвестной реализацией. Promo Engine и Smart Fulfillment показаны как существующие HQ-системы, без вымышленных интеграций с POS. Направление и формат потока продаж/остатков из магазинов ещё нужно установить.

Следующие проверки discovery: выборочная трасса импорта/выгрузки и доступов, инвентарь терминалов/ОС/фискальных устройств, журнал outage, перечень ограничений фискализации и маркировки, договоры SaaS/эквайринга/SAP, время работ сотрудников, структура 40% бюджета на legacy. До этого нельзя заключить, что любой POS SaaS закроет весь парк за пять дней или что 40% затрат исчезнут после отключения серверов.
